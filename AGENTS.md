# AGENTS.md — Octet (OCT): нерушимые правила репозитория

> Канон этого файла — `.agents/AGENTS.md`; корневой `AGENTS.md` и `CLAUDE.md` (со строкой `@AGENTS.md`) — входы для агентов.
> Файл ≤ ~100 строк: только проверяемые запреты, без пожеланий.

## 1. Контекст и навигация
- Стек: Python 3.12+ (reference-оракул, stdlib), CUDA 12.9 (sm_70/sm_86, nvcc),
  Rust 2024 (нода, Фаза 1+), pytest, GitHub Actions CI, GitHub repo helixn/octet.
- Карта архитектуры: `architecture-map.md` (обновлять после каждой задачи, меняющей структуру).
- Процедурные скилы: `.agents/skills/<имя>/SKILL.md`. Перед любой задачей — выбрать скил.
- Направление octet: `docs/DIRECTION-octet.md` (правила направления, порядок скилов).
- Приоритет правды: код и тесты > этот файл и SKILL.md > architecture-map.md > история чата.

## 2. Нерушимые правила архитектуры
1. **reference/ — оракул спеки** (`reference/octet_ref.py`): исполняемая форма
   `docs/pow.md`. Изменения ТОЛЬКО через скил `pow-spec-review` (vN → vN+1,
   delta-список, регенерация векторов). СТРОГИЙ ЗАПРЕТ править reference «под
   CUDA» или «под бенчмарк».
2. **cuda/ — производительность**: обязана совпадать с reference байт-в-байт
   на векторах. Любое расхождение = баг реализации. Работать только через
   `cuda-kernel-dev`. Скорость не повод менять математику.
3. **docs/ — контракты**: `docs/pow.md` (PoW vN), `docs/crypto.md` (PQ и
   приватность), `docs/DIRECTION-octet.md`. Спека опережает код: сначала правка
   спеки, потом реализация, никогда наоборот.
4. **Криптография**: СТРОГИЙ ЗАПРЕТ вводить ECDSA/EdDSA/ECDH/ring-sigs/ECC-SNARK
   в консенсус. Только ML-DSA / SLH-DSA / ML-KEM / BLAKE2b. Любое касание —
   скил `pq-crypto-review`.
5. **Консенсусные фичи** (всё, что попадёт в протокол блоков/нот/наград) —
   только через конвейер `pipeline` (Coder → Reviewer → Gate-панель 2/3).

## 3. Тесты и векторы
1. Тест-векторы reference — синтетические сиды; СТРОГИЙ ЗАПРЕТ генерировать
   векторы из «реалистичных» данных или хардкодить магические константы без
   происхождения (каждая константа ссылается на формулу спеки).
2. Защитный слепок (векторы ДО правки) обязателен перед любым изменением
   CUDA-этапа — `cuda-kernel-dev`, фаза 2.
3. Светлый путь (из кэша) и майнерский путь (из предвычисленного датасета)
   обязаны давать идентичный результат: тест-оракул в tests/.

## 4. Строгие запреты против обхода проверок (Anti-Cheat) и безопасность
КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:
- ослаблять/удалять/комментировать существующие проверки и тесты; `pytest.mark.skip`;
- `# noqa` / `# type: ignore` / `#![allow]` без письменного разрешения техлида;
- глушить исключения (`except Exception: pass`);
- снижать пороги CI и любые ворота (правило «только вверх»);
- менять reference до снятия защитного слепка (векторы);
- логировать токены, приватные ключи, сиды кошельков (Zero Auth Leak, CWE-532);
- выполнять мутирующие операции через read-only инструменты инспекции;
- автоматически вливать ветки/PR без явного вердикта гейта (Human-in-the-Loop).
Коммиты обязаны иметь префикс `[agent]` / `[assisted]` / `[manual]` (аудит происхождения).

## 5. Ворота готовности (Definition of Done)
Ни одна задача не считается выполненной, пока все команды подряд не вернули код 0:
1. `python -m pytest tests/ -q`
2. `scripts/dod_cuda.bat` (Windows) / `make -C cuda compile-only` (Linux/CI)
3. Нода (node/): `cargo clippy --release --workspace -- -D warnings && cargo test --release --workspace` — консенсусные векторы бит-в-байт

Зелёный pytest ≠ сдача. Задачи по спеке приёмка — только через рубрику
`orchestration/templates/gate-rubric.md`.

## 6. Использование процедурных скилов
1. Для каждой задачи найди скил в `.agents/skills/` и выполняй его фазы строго по порядку.
2. Не завершай работу, пока не закрыт Definition of Done активированного скила.
3. Сработало стоп-условие скила — остановись, откатись и доложи человеку
   (формат BLOCKED — в `ONBOARDING-AGENT.md`), а не обходи запрет.
