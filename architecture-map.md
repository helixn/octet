# Карта архитектуры и связей: Octet (OCT) — OctetHash v0.1

> Создана скилом `investigate-codebase` в режиме «только чтение», до первой правки.
> При расхождении с кодом — верить коду и обновлять документ. Обновлять после каждой задачи, меняющей структуру.

## 1. Как читать этот документ
Документ описывает слои проекта, направление зависимостей, консенсусные
контракты и зоны риска. Он не меняет код. Специфика Octet против HTTP-сервисов:
«эндпоинты» заменены на **контракты спеки**, а главное направление зависимостей —
не «транспорт→сервис→БД», а **спека → reference-оракул → CUDA → тесты**.

## 2. Слои и модули
- **Контракты (спека):** `docs/pow.md` (OctetHash v0.1), `docs/crypto.md`
  (PQ-подписи ML-DSA/SLH-DSA/ML-KEM, уровни приватности Tier 1–3),
  `docs/DIRECTION-octet.md`. Единственный источник истины по математике.
- **Reference-оракул:** `reference/octet_ref.py` — исполняемая спека,
  stdlib-only, два пути оценки (светлый из кэша / майнерский из датасета),
  профили: `FULL_SCALE` (8 ГБ, документация) и `TEST_PROFILE` (быстрые тесты).
- **GPU-солвер:** `cuda/octet.cu` + `cuda/fullscale.cuh` — этапы A/B/C
  (BLAKE2b device, cache fill, dataset expand, search) бит-в-байт сверены
  с оракулом: тест-профиль через `tests/vectors/`, полный масштаб (4 GiB,
  v0.3 genesis) через `tests/fullscale/` + `tests/verify_fullscale.py`
  (light-path верификация). Хост-API: `octet_device_count/status/selftest`.
- **Ворота:** `tests/test_octet_ref.py` (8 тестов: пути совпадают,
  детерминизм, re-key по блоку, tamper, target-search), `conftest.py`
  (sys.path), `scripts/dod_cuda.bat` (nvcc compile-check),
  `.github/workflows/ci.yml` (reference-tests + cuda-compile).
- **Харнес агентов:** `.agents/skills/*` (18 скилов), `orchestration/`
  (CODER→REVIEWER→GATE 2/3), `AGENTS.md`/`ONBOARDING-AGENT.md`, `specs/`.

## 3. Направление зависимостей
`docs/pow.md` → `reference/octet_ref.py` → `cuda/octet.cu` → `tests/`
Разрешённое направление — только сверху вниз. Запрещено:
- **CUDA/Rust менять reference** (reference — оракул; расхождение = баг реализации);
- **тесты подгонять под реализацию** (тест — оракул, чинится реализация);
- **менять параметры спеки из задачи** (параметры меняет только `pow-spec-review`,
  vN → vN+1);
- **вводить ECC-примитивы в консенсус** (только через `pq-crypto-review`).

## 4. Консенсусные контракты (менять запрещено без новой версии спеки)
| Контракт | Определение | Зафиксирован |
|---|---|---|
| Кэш эпохи | `cache[i] = H(cache[i-1] ‖ seed_epoch ‖ le64(i))` | pow.md §4.1 |
| Элемент датасета | цепочка из 32 родителей кэша, 4×64 Б = 256 Б | pow.md §4.2 |
| Re-key блока | `item_eff = item_base ⊕ keystream(seed_block)` | pow.md §4.3 |
| Поиск | 4096 полос × 16 раундов × 256 Б + butterfly | pow.md §5 |
| Адрес | `oct1… = Bech32m(BLAKE2b-256(ML-DSA pk))` | crypto.md §2 |
| Уровни приватности | Tier 1 (KEM stealth) → Tier 2 (ноты без zk) → Tier 3 (PQ-SNARK, research) | crypto.md §3 |

Потребители контрактов: будущая нода на Rust (Фаза 1+), CUDA-солвер,
CI-векторы, будущие кошельки/эксплореры.

## 5. Зоны риска
- **Консенсусная детерминизм:** расхождение GPU ↔ reference тихо портит
  цепочку. Контроль: бит-в-байт векторы до кода (`cuda-kernel-dev`, фаза 2).
- **Криптография:** любой ECC-примитив = квантовая уязвимость после генезиса.
  Контроль: `pq-crypto-review` на каждое касание.
- **Подгонка параметров под бенчмарк:** параметры меняет только протокол
  `pow-spec-review`, бенч не может править спеку.
- **Секреты:** только синтетические сиды в тестах; GitHub-токены/ключи
  кошельков в логи запрещены (CWE-532).
- **Целостность оракула:** reference меняется только по протоколу версий;
  ослабление тестов/ворот запрещено (AGENTS.md §4).

## 6. Внешние потребители
- Нода на Rust (Фаза 1+): повторит формулы §4 консенсусно.
- CUDA-солвер: майнинг; пользовательские карты sm_70/sm_86/sm_120.
- CI GitHub Actions: джобы reference-tests и cuda-compile — вход в merge.
- Будущие кошельки/эксплореры: адрес `oct1…`, формат нот (Tier 2).
