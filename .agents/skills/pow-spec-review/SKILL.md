# SKILL: pow-spec-review — правки спеки OctetHash

Цель: параметры консенсуса меняются осознанно, воспроизводимо и без
«подгонки под бенчмарк». Спека — контракт; это процедурное изменение контракта.

## Фазы (строго по порядку)

1. **Прочитай текущую спеку**: `docs/pow.md` (vN) и открытые вопросы §9.
   Выпиши, какие параметры затронет правка, и все зависимости (reference,
   тесты, CUDA, будущая нода).
2. **Мотивация одним абзацем**: что ломает текущая версия (атака, производительность,
   верификация) и почему правка это чинит. Нет мотивации — нет правки.
3. **Анализ атак ДО кода** (обязательный раздел правки): для каждой атаки из
   таблицы §8 спеки ответь, как меняется исход. Минимум: SRAM-ASIC,
   DRAM-ASIC, ботнет, аренда облака, precomputation, light-miner abuse.
4. **Новая версия спеки**: vN → vN+1 в `docs/pow.md`. Старая версия остаётся
   в git-истории; в шапке новой версии — delta-список изменений и мотивация.
5. **Регенерация тест-векторов**: обнови `TEST_PROFILE` при необходимости,
   прогони `pytest tests/ -q` — светлая и майнерская пути обязаны совпасть.
   Если расхождение — спека написана неоднозначно, вернись на фазу 4.
6. **DoD направления** (`octet/README.md`): pytest + `make -C cuda compile-only`.
7. **Приёмка**: любые правки спеки идут через конвейер `pipeline`
   (Reviewer + Gate-панель 2/3) — это консенсусный контракт, не рефакторинг.

## Стоп-условия (BLOCKED)
- Мотивация не формулируется одним абзацем → BLOCKED (недостаточно понимания).
- Правка ослабляет любой пункт таблицы атак без явного компенсирующего
  механизма → BLOCKED, доклад владельцу.
- Правка меняет модель нот/криптографию → передать `pq-crypto-review`.
