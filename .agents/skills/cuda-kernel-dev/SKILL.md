# SKILL: cuda-kernel-dev — GPU-солвер OctetHash

Цель: GPU-реализация обязана быть бит-в-байт эквивалентна reference.
Скорость — метрика Фазы, не повод менять математику.

## Фазы (строго по порядку)

1. **Investigate**: прочитай `docs/pow.md` (текущая версия), `reference/octet_ref.py`,
   `cuda/octet.cu`. Найди в карте какие кернеры существуют и какие stubs.
2. **Защитный слепок ДО кода**: сгенерируй векторы reference-ом для выбранного
   профиля (синтетические сиды, маленький профиль для скорости): JSON с
   `cache[], item_base[j], keystream[j], effective_item[j], states_after_round_r,
   final` — сохрани `tests/vectors_<profile>.json`. Эти векторы — оракул фаз 5–6.
3. **Кернеры**: реализуй по одному этапу за коммит: BLAKE2b-device → cache-fill
   → dataset-expand → rekey-sweep → search. Каждый этап — отдельный бенч-чек.
4. **Кросс-чек бит-в-байт**: хост-функция прогоняет те же векторы через GPU и
   сравнивает с JSON. Любое расхождение = BLOCKED (реализация, не спека).
5. **Бенчмарк**: `--bench N` на реальном железе, лог в `logs/bench_<gpu>.log`.
   Сравнение с предыдущим бенчем; регрессия >5% — объяснить или откатить.
6. **DoD направления**: `pytest tests/ -q` + `make -C cuda compile-only`
   + кросс-чек векторов на GPU (если GPU доступен; в CI — compile-only).

## Anti-Cheat
- Запрещено менять reference-реализацию «чтобы сошлось» — она оракул.
- Запрещено подбирать параметры под бенч (параметры меняет только
  `pow-spec-review`).
- Запрещено глушить проверку векторов (`#if 0`, skip, tolerate mismatches).
- Отладочные принты/сиды не попадают в main.

## Стоп-условия (BLOCKED)
- GPU недоступен и задача требует замеров → компиляция и векторный кросс-чек
  на CPU-эмуляции, замер BLOCKED-докладом.
- Расхождение с reference после двух итераций дебага → BLOCKED с дампом
  первого расхождения (этап, lane, индекс, ожидание/реальность).
