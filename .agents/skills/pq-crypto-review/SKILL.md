# SKILL: pq-crypto-review — криптография и приватность

Цель: ни один Shor-уязвимый примитив не попадает в консенсус Octet.
Спека решений: `docs/crypto.md`.

## Фазы (строго по порядку)

1. **Инвентаризация примитивов**: выпиши из затронутого кода/спеки ВСЕ
   криптографические операции (хэши, подписи, KEM, доказательства).
2. **Квантовый аудит каждой операции**: отвечает на вопрос «что делает
   алгоритм Шора с этим примитивом?»:
   - BLAKE2b / BLAKE3 — OK (Гровер квадратичен);
   - ML-DSA, SLH-DSA, ML-KEM — OK;
   - ECDSA, EdDSA, ECDH, ring sigs, Groth16/Halo2/PLONK — FAIL, замена
     обязательна, ответ — доклад владельцу, не «временно оставим».
3. **Приватность**: проверь, к какому уровню относится правка
   (docs/crypto.md §3: Tier 1/2/3) и не выходит ли правка за его границы
   (например, «скрытая сумма» без range-proof — это Tier 3, не Tier 2).
4. **Side-channel чек**: сравнения ключей/нот — constant-time; секреты не
   логируются; тестовые ключи — только синтетические сиды, никаких «реальных
   для правдоподобия».
5. **Размеры и экономика**: посчитай влияние на размер транзакции/блока
   (ML-DSA-65: sig 3309 B, pk 1952 B) и обнови бюджет блока, если правка
   его двигает.
6. **DoD**: pytest + `make -C cuda compile-only`; криптографическая правка
   всегда через конвейер `pipeline` (Gate-панель обязательна).

## Стоп-условия (BLOCKED)
- Найден ECC-примитив в консенсусном пути → BLOCKED с указанием файла/строки.
- Правка обещает приватность, недостижимую для её уровня → BLOCKED
  (продать Tier 2 как Tier 3 = уязвимость доверия).
- Нужен примитив, которого нет в NIST-стеке → BLOCKED, предложение альтернативы
  владельцу.
